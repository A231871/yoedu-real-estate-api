Feature Workflow Narrative:
1. Admin Suspension Request (POST /admin/moderation/listings/{id}/suspend):
   - Admin sends POST request with suspension reason. Controller validates admin principal and body.
   - AdminModerationServiceImpl verifies listing exists and is not already suspended, then publishes ListingSuspensionRequestedEvent and logs an AuditLog entry.
   - Endpoint returns HTTP 202 ACCEPTED immediately.
   - ListingSuspensionListener receives the event asynchronously, updates listing status to SUSPENDED inside listings domain transaction, and fires ListingSuspendedEvent.
   - NotificationEventListener receives ListingSuspendedEvent AFTER_COMMIT and dispatches in-app notification and email/push to the listing owner.
2. Status Polling (GET /admin/moderation/listings/{id}/status):
   - Admin UI polls status endpoint to track completion of async suspension.
3. Report Resolution (PUT /admin/moderation/reports/{id}/resolve):
   - Admin resolves report (RESOLVED / DISMISSED). If RESOLVED and suspendListing=true, emits ListingSuspensionRequestedEvent to trigger listing suspension cascade.
