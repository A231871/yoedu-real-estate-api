Feature Workflow Narrative:
- When an administrator requests GET /admin/moderation/listings/{id}/audit-history:
  - If the listing does not exist in the database, the system immediately returns HTTP 404 Not Found via NotFoundException — no Envers query is executed.
  - If the listing exists and has historical revisions, the system queries listings_aud and revinfo via Envers AuditReader, mapping each revision into a ListingAuditHistoryResponse (revision number, timestamp, revision type ADD/MOD/DEL, listing ID, title, status).
  - On DEL revisions where the entity snapshot is null, the system safely returns the listing ID from the path variable with null title/status instead of throwing NullPointerException.
- When an administrator requests GET /admin/moderation/audit-logs (with optional actorId, entityType, entityId query params):
  - All provided filters are combined dynamically via JPA Specification — passing actorId AND entityType applies both simultaneously; passing only entityType filters by entity type alone; passing no params returns all records.
  - Actor details are eagerly loaded via LEFT JOIN FETCH inside the Specification to prevent N+1 database queries.
  - Results are returned as a paginated AuditLogResponse list with actor details, action type, IP address, timestamp, and JSON payload fields.
